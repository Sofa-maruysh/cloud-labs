# Шпаргалка по nginx для лабы 1

## Что зачем

| Директива | Где | Зачем в лабе |
| --- | --- | --- |
| `listen 443 ssl` | оба виртуальных хоста | HTTPS с самоподписанным сертификатом |
| `return 301 https://$host$request_uri` | server на 80 порту | принудительный редирект HTTP → HTTPS |
| `upstream backend { ... }` | http | пул из двух бэкендов для балансировки `/api` |
| `proxy_pass http://backend` | `location /api` | проксирование API на пул |
| `alias` | `location /docs` | псевдоним пути: отдельная папка отдаётся по `/docs` |
| `server_name` | каждый server | виртуальные хосты: разведение запросов по доменам |
| `limit_req_zone` / `limit_req` | http / `location /api` | ограничение частоты запросов, при превышении — 429 |
| `error_page 404 /404.html` | server | своя страница 404 |
| `auth_basic` + `auth_basic_user_file` | `location /admin` | базовая авторизация раздела |

## Отказоустойчивость

Если один сервер из `upstream` недоступен, `proxy_next_upstream` направляет
запрос на следующий. Для быстрого переключения дополнительно заданы короткий
`proxy_connect_timeout`, число попыток и общий таймаут переключения. Поэтому
при остановке одного из двух бэкендов `/api` продолжает отвечать 200 со второго.
